# 4. shadcn/ui, Tailwind and Sonner for the UI

- Status: Accepted
- Date: 2026-11-08

## Context

The web app needs a consistent set of accessible UI primitives, and toasts for things like the update notice. We want contributors and AI agents to build UI the same way, without us maintaining a component library.

## Decision

- **Components:** [shadcn/ui](https://ui.shadcn.com) (Radix base, `radix-nova` preset). Components are copied into `apps/web/src/components/ui` by the CLI and owned by this repo.
- **Styling:** Tailwind CSS v4 through `@tailwindcss/vite`. Theme tokens are CSS variables in `apps/web/src/styles.css`.
- **Toasts:** Sonner, through the shadcn component. One `<Toaster />` is mounted in the root route. No second toast library.
- **Adding components:** `pnpm dlx shadcn@latest add <name>` from `apps/web`, only what a change needs. Never `add --all`.
- **Biome:** the CSS parser has `tailwindDirectives` enabled so Tailwind syntax lints and formats.

## Consequences

- We own the code of every component we add, so updates are manual (re-run the CLI and review the diff). CodeRabbit skips `ui/` in its path filters; review changes there by hand.
- Sonner registers its own keyboard shortcut (`Alt+T`, focuses the toast region). It is the only keyboard route to reach toasts, so it stays enabled and must be listed in the `Cmd+/` shortcut list when that exists. See `docs/internals/hotkeys.md`. Source: the installed `sonner@2.0.8` code (`Toaster` defaults `hotkey` to `['altKey', 'KeyT']`, binds it on `keydown`, and takes the toast region out of normal tab order), read 2026-11-08.
- `components/ui/sonner.tsx` imports `useTheme` from `next-themes`. Source: the file generated by `shadcn add sonner` (shadcn CLI 4.x), read 2026-11-08. No theme provider is mounted yet, so Sonner follows the system theme (`useTheme` default `"system"` in that file). Dark mode setup is a later decision.
- The shadcn CLI installs packages we use at build time (`tw-animate-css`, `@fontsource-variable/geist`, `lucide-react`, `cn`, `next-themes`, `sonner`). The `shadcn` package itself is a **dev dependency**: the stylesheet imports `shadcn/tailwind.css` from it, but nothing from it ships in the Worker bundle. Its transitive dependencies `minimatch` (GHSA-g3hv-75wg-m249, fixed in 11.x, pinned to 10.x by `ts-morph`) and `deepmerge` (GHSA-gcqx-w48m-w2h4, no patched version) have open Dependabot alerts that come only through this CLI. They affect the CLI's own handling of attacker-controlled input, not app users. Leave the alerts open; they clear when upstream updates. Source: `pnpm why`, the GitHub advisories, and Dependabot alerts #1 and #2, read 2026-11-08.
- Initial setup note: `shadcn init` did not complete unattended for this TanStack Start layout (it assumed `app/globals.css` and React Server Components). `components.json` was corrected by hand (`rsc: false`, CSS at `src/styles.css`). Re-running `init` is not needed.
